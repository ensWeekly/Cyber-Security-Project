## Publish on GitHub Pages

1. Download and extract this ZIP on your computer. Do not upload the ZIP itself.
2. Sign in to GitHub. Create a new public repository called `grade11-cybersecurity`. Choose **Add a README file** when creating it.
3. In the repository, choose **Add file → Upload files**. Upload the extracted **index.html** directly to the repository root (the same level as README.md). The website is self-contained: only index.html is required.
4. Select **Commit changes**.
5. Go to **Settings → Pages**. Under Build and deployment, choose **Deploy from a branch**. Select **main** and **/(root)**, then **Save**.
6. Wait for GitHub's deployment to finish. Refresh Settings → Pages and use **Visit site**. Copy the actual URL displayed there and share it with students.
7. To update the site, upload a replacement index.html to the same repository and commit it. Do not create a second repository for routine updates.

GitHub's instructions: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

The download is ready to publish, but it has not been uploaded to your GitHub account. Students do not need GitHub accounts to use the published site.

## What students do

Two lessons of 55 minutes. Individual project with a partner for testing. Choose one fictional school privacy case, manually encode/decode a message, build a four-stage secure communication design, run two tabletop tests, improve one rule, and create a privacy advice card.

No coding or paid software is required. A desktop, laptop or tablet browser works. Paper is needed for handwritten cipher evidence. Students should write concise responses; this is a prototype and evidence report, not a full software build.

## Minimal AI use

Student policy: no AI-generated project content, designs or test records. Only teacher-approved spelling/grammar checking after an original draft is allowed, with changes declared and the original retained. Use in-class work, handwritten cipher evidence, observed checkpoints, real partner observations and brief oral questions to assess understanding. No AI detector or paste-blocking claim is made.

## Saving and submission

- Responses stay in the current browser profile using local storage when available. This is not a secure data vault. Use invented details and student codes.
- Students should download a **JSON backup** at the end of each lesson. A backup can be restored on another device using **Restore a backup**.
- **Print / save report as PDF** opens the browser print dialog. Choose Save as PDF on a computer, or the available print/share PDF workflow on the tablet. The report includes the current answers, prototype, card and a teacher marking record. It can be exported as a draft when fields are missing.
- Upload the PDF to the school platform you specify. The site does not send work, assign marks or provide a teacher dashboard.
- Public GitHub Pages hosts the instructions, not student reports. Never upload student responses or backups into the public repository.
- On shared devices, download the report and backup, then clear the device's work using the provided button.
- The Teacher guide tab has practical support, extension, checkpoint and assessment guidance. It is public guidance, not a secure teacher area.

## Learning alignment

PG 6: Recognize and analyze security concepts. **CS.HS.4.2**: Encryption is fundamental to data security and privacy and is important in cybersecurity. Alignment uses the teacher-supplied unit description. The project covers permissions, breaches, privacy vs convenience, anonymity, identity, long-term consequences and responsible communication in a fictional UAE school context.

The Caesar activity illustrates substitution and key use. It is explicitly not secure enough for real private communication. The proposed system uses real encryption concepts (TLS or end-to-end encryption), identity/access controls, storage safeguards and a breach response. No real attacks or live security testing are required.
